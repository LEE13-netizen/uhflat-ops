## 1. 실제 데이터 분석 (STEP 1)
- **예약 품질 양호**: 예약끼리 겹침 0건, 0박 0건, 이름·연락처 없음(개인정보 확인).
- **운영 패턴**
  - 만실 기간(10/26~11/9): 점유 95~99%, 퇴실 47~88실/일, 퇴실 객실의 대부분이 당일 재입실(퇴실·입실). → "40% 퇴실 만실" 가정은 실제 최고치(88실 = 38%)와 일치
  - 숙박일수: 평균 4.1박, 중앙 3박, 1박 31%, 7박 이상 16.5%, 30박 이상 11건(10실)
  - 재실 객실: 하루 평균 129실, 그중 전체 청소 대상 평균 43실(최대 78)
  - 요일별 퇴실은 고르게 46~55실 → 요일보다 날짜별 변동이 큼
  - 11/10 이후 점유 38~56%(예약표 기준)
- **데이터 문제**: 예약표의 표기 칸(UHC·Miss 등) 411건 중 388건이 서로 겹침. 원인은 이어진 표기 칸을 날마다 새 기간으로 저장하는 파서(`js/rooms.js` spansFrom). 508호 한 곳이 188건 → **수정함**(합치면 411 → 23건)
- **저장 구조**
  - 표 하나(ops_docs)에 모음별 JSON 문서. 날짜별 객실 상태(약 2KB/일)
  - 청소 기록은 날짜×객실 문서로 실제 패턴 기준 하루 약 200건, 월 약 6MB
  - **모든 기기가 시작할 때 청소 기록·업무·이력 전체를 내려받고 화면에서 날짜로 거른다**(`watchWhere`가 서버 필터가 아님) → 몇 달 뒤 느려짐(PERFORMANCE P1)
- **자동화 가능**: 재실 요청 입력(하루 129실 중 대부분 기본 정비면 "거절만 입력"), 전체 청소 주기, 7일 점검(이미 있음), 15시 입실 위험 경고, 시설 완료 → 객실 해제 알림

## 4. 마감·인수인계 설계 방향 (F-1·F-2·O-2, 구현 전 결정 필요)
- **근무 단위**: 부서 × 근무(주간·야간). 이미 있는 "인수 확인"을 근무 마감으로 넓힌다
- **마감 요청 화면**: 자동으로 모은다 — 미완료 업무 · 아직 입실 가능 아닌 퇴실 객실 · 안 한 재실 요청 · 열린 불출 · 미확인 전달 · 오늘 필수 입력(수건 재고 등)
- **항목마다 처리**: 끝내기 / 사유를 적고 **이월** / 다음 근무자에게 메모
- **마감 가능 판정**: 이월 사유 없는 미완료가 0일 때만. 부서장은 사유를 남기고 강제 마감
- **마감 후**: 그 근무 기록은 일반 직원이 고치지 못한다. SYSTEM OWNER 정정은 전후 값이 감사 기록에 남는다(DB 규칙, 0009와 같은 방식)
- **다음 업무일**: 이월 항목이 "넘어온 것"으로 뜬다. 청소 기록도 이월(O-2)
- **과거 조회**: 보관함·이력에서 날짜로 조회(지금 구조 유지)

### 8-5. 키핑 담당(룸메이드) 배정 · 내 방
- **배정 = 구글시트 청소표의 "담당" 칸**(본관 K열·신관 J열, 머리글 "담당" 우선, 없으면 메모/비고 오른쪽 두 번째). 청소표를 올리면 그날 객실별 담당으로 저장. 숫자·시간이 잘못 들어간 칸은 버림, "박서연 / 최유나"처럼 두 명이면 두 사람 모두의 방
- **부서장 수정**: 키핑 부서장·SYSTEM OWNER는 청소·재실의 "담당 바꾸기"로 방마다 바꿈(청소표보다 우선, 누가 바꿨는지 기록). "청소표대로"로 되돌림
- **내 방**: 개인 계정은 로그인 이름으로, 부서 공용 계정은 기기마다 "내 이름" 한 번 고름. 맨 위 "○○님 담당 N실 · 내 방 / 전체" — 내 방은 본관·신관 모두에서, 현황판에는 내 방 테두리. 동 전체 숫자는 접어 둠
- **프론트**: 청소·재실 줄마다 담당 이름
- 이름 맞추기: 띄어쓰기 무시, 짧게 적은 이름("민지")도 맞춤 — **같은 글자가 들어간 이름이 둘이면(김민지·이민지에 "민지") 둘 다 맞으므로 청소표에는 성까지 적는 것을 권장**
- 시험: 청소표 모양 엑셀로 읽기 확인(본관·신관·두 명·잘못된 값), 화면 8항목 통과(이름 고르기·내 방만·전체·현황판 테두리·두 명 칸·부서장 변경·되돌리기·프론트 표시)
