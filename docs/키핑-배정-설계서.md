# 키핑 객실 배정 · 정비 순서 · 점검 순서 설계서 (안)

시뮬레이션 근거: `tools/sim/ops-day-sim.js`(실제 엔진 사용), 만실 232실 · 퇴실 93 · 재실 139, 프론트 7 · 룸메이드 20 · 인스펙터 3 · 하우스맨 2 · 시설 2.
배정 방식 5 × 정비 순서 3 × 점검 순서 2 × 평상시/나쁜 날, 시드 3~5개 평균. 나쁜 날 = 1명 결근, 13시 2명 조퇴, 오후 재실 요청 15건 추가.

## 1. 결론
**권장: "작업량 균등 구역 배정 + 끝나면 도와주기(잡기 잠금)"**
- 아침에 동별로 룸메이드마다 연속된 층·객실을 작업량(점수)이 같도록 나눈다. 시스템이 제안하고 사람이 고친다.
- 자기 방이 끝나면 **먼저 자기 구역의 퇴실 전 객실을 확인**한다. 그다음 시스템이 "가장 밀린 동료의 방"을 하나씩 제안하고, 누른 사람만 잡는다(서버 잠금).
- 정비 순서: 우선 준비(이른 입실) → 퇴실 완료 순 → 재실은 요청 시간 시작 후. 단 **13시 전까지는** 요청 시간이 50분 안에 끝나는 재실을 끼워 넣는다. 13시 이후는 15시 입실 우선.
- 점검 순서: 입실 시각이 급한 순(우선 준비 먼저), 같으면 오래 기다린 순.
- 인스펙터는 3명 유지. 4명은 점검 대기를 크게 줄이지만 15시 준비 수는 그대로이고, 룸메이드가 1명 줄어 재실 지연이 10%p 늘었다.

## 2. 비교 (평균)
| 방식 | 15시 입실 가능 /93 | 재실 지연 | 같은 방 중복 | 룸메이드 마지막 작업 | 나쁜 날 15시 | 나쁜 날 재실 지연 |
|---|---|---|---|---|---|---|
| 지금(동 전체 한 목록) | 80.6~82.4 | 55~67% | 하루 약 390~440회 | 16:57~17:05 | 80.6~82 | 58~74% |
| 층 균등 고정 | 82.2~83.4 | 32~37% | 0 | 17:12~17:23 | 79.4~81.4 | 36~42% |
| 작업량 균등 고정 | 84.8~86.2 | 31~35% | 0 | 16:30~16:38 | 83.6~83.8 | 39~43% |
| 시스템이 한 방씩 배정 | 83.6 | 19~24% | 0 | 15:42 | 82~82.2 | 37~46% |
| **작업량 균등 + 도와주기** | **86.2~86.8** | **24~29%** | **0** | **15:53** | **84.2~85** | **32~36%** |

- 15시 입실 가능 최대치는 약 87실이다. 나머지 6~7실은 레이트 체크아웃(13시·14시 퇴실)이라 배정 방식으로 풀리지 않는다.
- "시스템이 한 방씩"은 재실 지연이 가장 낮지만 퇴실 확인 순회가 밀려(퇴실 확인 평균 11:05) 15시 준비가 떨어지고, 나쁜 날에 약하다. 층을 오가는 거리도 가장 길다.
- 도와주기는 걷는 거리가 고정 배정보다 약 35% 늘어난다(1인당 하루 약 9분). 같은 동·가까운 층을 먼저 제안해 줄인다.
- 정비 순서 "13시 전 끼워 넣기"는 재실 지연을 약 5%p 줄이는 대신 15시 준비가 평균 0.6실 줄었다. 지점 설정으로 둔다.

### 시뮬레이션에서 찾은 함정과 조치
| 함정 | 근거 | 조치 |
|---|---|---|

| 결근·조퇴자 방이 남음 | 고정 배정은 14:30 손으로 다시 나눌 때까지 방치 | 부서장 "구역 풀기" → 그 방들이 바로 도와주기 대상 |

| 동시 수정으로 기록 사라짐 | 모든 방식에서 하루 5~8건(키핑 확인) | 객실 청소 기록을 서버 병합 저장으로 바꿈(배정과 같이) |
| 점검 대기 | 90%가 50~67분 안. 4명이면 10~20분 | 3명 유지 + 점검 대기 몇 분째인지 보이기 + 15시 위험 경고 |
| 오전 대기 | 룸메이드 1인당 평균 약 200분이 할 방 없음(대부분 10~11시 퇴실 전) | 출근 시차(예: 일부 09:30 출근·18시 퇴근) — 다음 시뮬레이션으로 확인 |

## 4. 화면
### 배정판 (HK 부서장 · 배정 담당)
- 동별 탭 → 출근자 체크 → 룸메이드마다 한 줄: 담당 층·객실 칩, 작업량 막대(점수 합), 퇴실 수·재실 수
- "자동 나누기": 층 순서대로 이어 붙이며 점수가 같아지게 자른다
- 방 칩을 누르고 → 다른 룸메이드를 누르면 옮김. 점수 막대가 바로 바뀜
- "확정"해야 룸메이드 휴대폰에 뜬다. 확정 뒤 바꾸면 해당 룸메이드에게 알림
- 작업량 점수(설정에서 바꿈): 퇴실 1.0 · 전체 청소 0.75 · 일반 청소 0.35. 아침엔 재실 요청을 다 모르므로 재실은 0.85를 곱한 기대값

### 룸메이드: 내 방
- 맨 위 큰 카드 = 다음 방 하나(이유: "우선 준비 13:00", "퇴실 완료 10:42", "요청 11~13시, 40분 남음")
- 버튼: 청소 시작 → 청소 끝(퇴실은 점검 대기로, 재실은 완료). **재실에도 "청소 시작"** (지금은 없음)
- 아래: 내 남은 방 목록, 내 구역 퇴실 전 객실(두드려 확인)
- 다 끝나면 "도와주기" 카드: 누구 구역 몇 호, 이유(밀린 정도). "잡기" → 내 방으로

### 인스펙터: 점검 대기
- 입실 급한 순, 각 줄에 "점검 대기 N분", 15시까지 남은 시간
- 열린 수리 업무가 있는 방은 입실 가능 누를 때 경고(별도 항목, 같이 넣기 권장)

### 프론트·현황판
- 객실 칸에 담당자 이름(짧게), 동별 진행률(룸메이드별 완료/남은 점수)

## 5. 데이터 · 서버
- **배정**: `roomSvc` 문서(날짜__객실)에 `asg: { uid, name, at, by }`. 아침 배정·옮기기·도와주기 잡기가 모두 이 칸 하나를 쓴다
- **배정 계획**: `hkPlan` 모음, 문서 id = 날짜__동. `{ crew: [uid…], absent: [uid…], weights, confirmedAt, by }`
- **잡기 잠금**: 서버 함수 `ops_claim(col, id, key, value)`: 그 칸이 비었거나 같은 사람일 때만 쓰고, 아니면 현재 주인을 돌려준다(한 번의 조건부 갱신이라 동시에 눌러도 한 명만)
- **기록 사라짐 해결(같이 진행)**: 객실 청소 기록 저장을 통째 덮어쓰기(`Store.set`)에서 칸 병합(`Store.update` → `ops_patch`)으로 바꾸고, 이력(log)은 서버 함수가 앞에 덧붙인다
- **권한**: 배정판 확정·옮기기·구역 풀기 = HK 부서장 + 배정 담당. 도와주기 잡기 = 모든 키핑. RLS는 지금 `ops_docs`처럼 같은 지점이면 쓰기 가능이라 화면에서 막고, 서버 함수 `ops_claim`에서 역할을 한 번 더 본다
- **"키핑 확인"**: 배정된 방은 담당자 확인으로(다른 룸메이드가 눌러도 담당자의 깜빡임은 남김)

## 6. 단계
1. 배정판(자동 나누기·옮기기·확정) + 내 방 + 재실 청소 시작 + `ops_claim` + 병합 저장
2. 도와주기 제안 + 구역 풀기 + 담당자 확인
3. 점검 대기 정렬·대기 시간 + 14시 경고 + 열린 수리 업무 경고
각 단계: 시뮬레이션 다시 돌림 → 시험 환경 → 운영.
